## 4. 周末验收脚本

在记录了引擎版本、Git 提交／工作区状态、操作系统、窗口尺寸和输入设备的构建上执行：

1. 从 README 指定入口启动，进入小镇；按四方向行走、冲刺、顶墙、转角，确认没有穿墙或角色残留。
2. 走近两名 NPC，只对当前目标显示提示；打开并关闭占位对白，确认背景角色不响应同一次确认键。
3. 找到文书并查看；离开区域后返回，确认已检查标记保留。
4. 在街巷选择住所或码头，读取出口目的地，切换后检查落点；两个方向至少往返五次。
5. 测试 1280×720、1366×768 和全屏；检查人物比例、文字可读性和镜头边界。
6. 只用键盘完整走一遍；保留手柄动作绑定及已有模拟回归，模拟结果明确标注。实体手柄全流程按后续里程碑验收，不作为本周通过条件；若提前实测，另记型号和结果。
7. 退出并重新启动，确认没有错误和崩溃。跨进程探索状态恢复只有已接入该状态的存档任务验收后才计通过，不因基础存档服务存在而默认通过。

周末通过标准：上述目标相关行为均有证据，没有阻断探索的 P0／P1；新版速度与存档 UI 由开发者复测。原“新玩家无口头指路找到两个出口与一次交互”要求继续保留，但按 2026-09-22 用户明确授权登记 P2，第四周闭环评审检查安排，不再阻断本轮修改。体验时长如实记录，不用原 7 分钟冒充十分钟。手感问题描述具体速度、转向、镜头、提示或路线问题，避免只写“感觉不好”。
